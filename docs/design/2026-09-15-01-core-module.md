# core 模块执行计划书

| 项目 | 内容 |
|------|------|
| 所属项目 | AI 智能面试助手 MVP |
| 依据 PRD | docs/prd/2026-09-15-ai-interview-assistant-mvp-prd.md |
| 模块 | core（公共能力） |
| 状态 | 待评审 |
| 实现顺序 | 第 1 个模块（无前置依赖） |

---

## 1. 模块目标

为后端所有业务模块提供公共基础能力：应用配置、数据库连接与会话管理、依赖注入、统一异常处理、匿名用户标识解析。core 是纯基础设施模块，自身不依赖任何业务模块，是其它所有后端模块的底层依赖。

## 2. 职责边界

**做什么：**

- 应用配置加载与访问（数据库路径、服务端口、题库种子数据路径等）。
- 数据库引擎与会话（Session）的创建与管理，基于 SQLite。
- 依赖注入机制（基于 FastAPI `Depends`），为各 router 提供：数据库会话、各 service 实例。
- 统一异常处理：将业务异常与未知异常转换为统一的 JSON 错误结构。

**不做什么：**

- 不包含任何具体业务逻辑（题目、会话、报告、模板等）。
- 不实现 LLM / 面试引擎相关能力。
- 不处理前端页面与路由。

## 3. 依赖关系

- **依赖**：无（仅依赖框架与第三方库：FastAPI、SQLAlchemy、Pydantic）。
- **被依赖**：questions、engine、templates、interviews、reports 全部模块。

## 4. 文件结构

```
backend/app/core/
  config.py        # 配置模型与加载逻辑
  database.py      # SQLAlchemy engine、SessionLocal、声明基类 Base
  deps.py          # 依赖注入：get_db、get_xxx_service
  exceptions.py    # 异常体系：应用异常基类与通用业务异常
  handlers.py      # 统一异常处理器注册
  schemas.py       # 统一响应 / 错误结构
```

> 说明：core 是基础设施包，不遵循 `router → service → repository` 三层结构；该分层约束适用于各业务模块。

## 5. 数据模型

core 自身不定义业务实体，仅提供被各模块复用的模型基类：

| 基类/约定 | 说明 |
|-----------|------|
| `Base` | SQLAlchemy 声明基类，所有业务模块的 models 均继承自它 |
| 主键约定 | 统一使用自增整数主键 `id` |
| 时间戳约定 | 各实体如需时间字段，统一采用 `created_at` / `updated_at` 命名 |

## 6. 接口设计

### 6.1 配置

| 配置项 | 说明 | 默认值（建议） |
|--------|------|----------------|
| `database_url` | SQLite 连接串 | `sqlite:///./interview.db` |
| `seed_questions_path` | 题库种子数据文件路径 | `backend/app/questions/seed_data.json` |
| `request_body_limit` | 请求体大小上限 | 1 MB |

配置来源优先级：环境变量 > 默认值。配置对象在应用启动时加载一次，供各模块读取。

### 6.2 数据库会话

- `get_db()`：依赖注入提供数据库会话，请求结束时自动关闭/回滚。
- 通过 repository 层隔离具体数据库，替换 PostgreSQL 时仅需修改本模块与各 repository 的连接方式。

### 6.3 统一异常与响应

| 结构 | 字段 | 说明 |
|------|------|------|
| 成功响应 | `code` / `message` / `data` | `code=0` 表示成功 |
| 错误响应 | `code` / `message` | 非 0 错误码 + 可读错误信息 |
| 业务异常基类 | `code` / `message` / `status_code` | 各模块抛出的业务异常统一继承 |

统一异常处理器行为：

- 业务异常 → 按异常携带的 `status_code` 返回统一错误结构。
- 参数校验异常（Pydantic / FastAPI）→ 400 + 统一错误结构。
- 未知异常 → 500 + 通用错误信息（不泄露堆栈）。

## 7. 关键设计决策

1. **数据库隔离**：SQLite + SQLAlchemy，repository 层统一抽象，满足 PRD「数据库可替换」。
2. **依赖注入**：采用 FastAPI 原生 `Depends`，不引入额外 DI 容器。
3. **统一错误结构**：前端 `api.js` 依赖此结构做统一处理，因此错误格式需在 core 层一次性定死。
4. **匿名标识交由 users 模块处理**：PRD 6.4 要求的 `X-Client-Id` 解析与校验由独立的 users 模块负责，core 不再承担该职责。

## 8. 验收标准

- 应用可启动，SQLite 数据库文件自动创建。
- 业务模块抛出的业务异常能转换为统一错误结构。
- 未知异常返回 500 + 通用信息，不向客户端泄露堆栈。
- questions 等后续模块可正常通过依赖注入获取数据库会话与匿名标识。
