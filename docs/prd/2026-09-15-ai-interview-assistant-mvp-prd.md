---

## 1. 产品概述

### 1.1 背景

求职者在参加真实面试前，往往缺乏充分的模拟练习机会：没有合适的面试官、缺少针对性反馈、练习成本高。本项目提供一款 AI 面试陪练工具，由 AI 扮演面试官，求职者通过文字对话完成一次结构化模拟面试，并在结束后获得每题点评与整体改进建议，从而熟悉面试流程、发现自身不足、提升面试表现。

### 1.2 产品定位

面向求职者的 AI 面试陪练 Web 应用（PC 端）。

### 1.3 目标用户

- 正在准备求职面试的求职者（校招 / 社招）。
- 希望提升面试表达、熟悉常见面试题的人群。

### 1.4 核心价值

- **零成本、随时随地**：无需真人面试官，打开浏览器即可练习。
- **结构化流程**：按岗位方向、题型、轮数定制面试，贴近真实面试节奏。
- **针对性反馈**：每道题有文字点评，整体有改进建议。

## 2. 范围

### 2.1 MVP 范围内

1. 面试配置：选择预设模板或自定义面试（岗位方向、题型组合、题目数量）。
2. 面试进行：AI 逐题以文字提问，用户文字作答，显示进度，支持提前结束。
3. 评估报告：面试结束后生成报告，包含每题点评、总体评价、改进建议。
4. 历史记录：按浏览器匿名标识查看过往面试记录及其报告。
5. 题库：内置多岗位（技术 / 产品 / 运营 / 通用行为题）题目，约 100–200 题。
6. 技术架构：前后端分离；后端严格分层（router / service / repository），每个业务模块一个包；预留 LLM Provider 抽象接口。

### 2.2 MVP 范围外（明确不做）

- 语音交互（语音识别 / 语音合成）。
- 移动端适配。
- 用户注册 / 登录体系（仅使用浏览器匿名标识）。
- 真实大模型接入（本期用规则模拟，仅预留抽象接口）。
- 题库管理前端界面（后端提供题库数据能力即可）。
- 动态追问（AI 不基于回答内容进行开放式追问）。
- 多语言、暗色主题等体验增强。

## 3. 用户画像与使用场景

**典型用户**：一名准备后端开发岗位面试的求职者。

**核心场景**：

1. 用户打开应用，进入首页。
2. 选择岗位方向「技术-后端」、题型组合与题目数量（或直接选用预设模板）。
3. 点击「开始面试」，AI 以文字逐题提问。
4. 用户逐题作答，AI 给出点评后进入下一题。
5. 全部题目完成后，进入报告页查看总体评价与改进建议。
6. 用户可随时在历史页回顾过往练习与报告。

## 4. 功能需求

### F1 面试配置

**用户故事**：作为求职者，我希望在开始面试前选择岗位和题型，以便练习与我目标岗位匹配的题目。

**功能描述**：

- 首页提供「预设模板」与「自定义配置」两种入口。
- 预设模板：内置若干套组合（如「前端开发面试」「通用行为面试」「产品经理面试」等），一键开始。
- 自定义配置项：
  - 岗位方向：技术-前端 / 技术-后端 / 技术-算法 / 产品 / 运营 / 通用。
  - 题型组合：自我介绍、技术题、行为题、项目经验题、开放题（可多选）。
  - 题目数量：1–20 题（由各题型题目数之和决定）。
- 用户点击「开始面试」后创建会话并进入面试页。

**验收标准**：

- 用户可选择预设模板或自定义配置。
- 配置无效时（如未选题型、题数为 0）给出明确提示且不允许开始。
- 开始面试后，后端按配置生成面试题目序列并返回第一题。

### F2 面试进行

**用户故事**：作为求职者，我希望与 AI 逐题对话，并在作答后得到即时反馈，从而知道自己的回答是否到位。

**功能描述**：

- 面试页以对话形式展示 AI 提问与用户回答。
- 显示当前进度：第 N 题 / 共 M 题。
- 用户提交回答后：
  - 若还有下一题，返回下一题（并附带本题点评）。
  - 若为最后一题，返回本题点评并标记面试完成。
- 支持「提前结束面试」，已完成的题目仍纳入报告。
- 对空回答或过短回答，给出一句固定提示（不进入下一题）。

**验收标准**：

- 题目按配置顺序逐题呈现，进度显示正确。
- 每题提交后返回点评，最后一题提交后面试状态变为「已完成」。
- 提前结束后，会话状态变为「已结束」，已作答题目可生成报告。
- 空 / 过短回答被拦截并提示，不计入有效作答。

### F3 评估报告

**用户故事**：作为求职者，我希望面试结束后看到整体评价和改进建议，从而知道自己的薄弱点。

**功能描述**：

- 面试完成后自动生成报告，内容包含：
  - 总体评价（文字）。
  - 改进建议（文字）。
  - 每题点评：题目、我的回答、AI 点评。
- 报告页可查看完整报告。
- 提前结束的面试同样生成报告（基于已作答题目）。

**验收标准**：

- 面试完成后可进入报告页，报告内容完整（总体评价 + 改进建议 + 每题点评）。
- 报告与历史会话正确关联，可重复查看。

> **说明**：MVP 采用「规则模拟」点评，即基于题目预设的参考要点给出点评模板，不依赖大模型的语义理解。这是本期已知限制，接入真实大模型后点评质量将显著提升。

### F4 历史记录

**用户故事**：作为求职者，我希望查看过往的练习记录与报告，以便回顾和对比进步。

**功能描述**：

- 历史页按时间倒序列出当前浏览器（匿名标识）下的所有会话。
- 每条记录展示：岗位方向、题目数量、开始时间、状态（已完成 / 已结束）。
- 点击记录进入对应报告页。

**验收标准**：

- 历史列表只显示当前浏览器匿名标识对应的记录。
- 记录信息准确，可正常跳转查看报告。

## 5. 非功能需求

| 类别 | 需求 |
|------|------|
| 性能 | 常规接口响应时间 < 500ms；面试题 / 报告加载流畅，无明显卡顿。 |
| 兼容性 | 支持主流 PC 浏览器最新两个大版本（Chrome / Edge / Firefox）。 |
| 可用性 | 界面简洁清晰；关键操作（开始、提交、结束）有明确反馈；异常时有友好提示。 |
| 安全 | 后端对用户输入做校验与转义，防止注入；对请求体大小做限制。 |
| 可维护性 | 后端严格分层（router / service / repository），每个业务模块一个包；前端 JS 按页面拆分。 |
| 可扩展性 | 通过 `engine` 抽象层预留真实大模型接入点；数据访问层隔离，数据库可替换。 |
| 部署 | MVP 单机可运行，无外部依赖（不依赖真实大模型 API）。 |

## 6. 技术架构约束

以下为需求层面的架构约束，实现阶段需严格遵守：

### 6.1 总体架构

- 前后端分离，通过 REST API（JSON）通信。
- 前端：原生 HTML + CSS + JavaScript（不使用前端框架）。
- 后端：Python + FastAPI。
- 数据库：SQLite（零部署；通过 repository 层隔离，后续可替换为 PostgreSQL）。

### 6.2 后端分层与模块化

- 后端按业务模块划分包（package），**每个模块一个包**。
- 每个包内部严格分层，依赖方向固定为 `router → service → repository`，不得反向依赖。
- 计划模块划分：

```
backend/app/
  core/        公共能力：配置、数据库连接、依赖注入、统一异常处理
  engine/      AI 面试引擎抽象（InterviewEngine 接口）+ 规则实现
  questions/   题库模块（题目存储与筛选）
  templates/   面试模板模块（预设模板与自定义配置校验）
  interviews/  面试会话模块（会话创建、对话流转、状态机、历史列表）
  reports/     评估报告模块（报告生成与查询）
```

- 各模块包内建议文件结构（以 `questions` 为例）：

```
questions/
  router.py        # HTTP 层：参数校验、调用 service
  service.py       # 业务逻辑：题目筛选规则
  repository.py    # 数据访问：题目增删改查
  models.py        # 数据模型
  schemas.py       # 请求 / 响应模型
```

### 6.3 关键抽象：engine 模块

- 定义 `InterviewEngine` 接口，抽象出「出题」「点评」等能力。
- 上层 `interviews`、`reports` 模块只依赖该接口，不感知具体实现。
- MVP 提供 `RuleBasedEngine` 规则实现（按模板从题库抽题、按参考要点生成点评）。
- 未来新增 `LLMEngine` 实现接入真实大模型，**上层模块零改动**。

### 6.4 匿名用户标识

- 免登录模式下，前端生成一个匿名标识（UUID），存储于浏览器 localStorage。
- 每次请求携带该标识（如请求头 `X-Client-Id`），后端据此区分不同浏览器用户的历史记录。

### 6.5 前端结构

```
frontend/
  index.html      面试配置页（首页）
  interview.html  面试进行页
  report.html     评估报告页
  history.html    历史记录页
  css/            共享样式
  js/api.js       请求封装（fetch）
  js/*.js         各页面逻辑
```

## 7. 数据模型概要

| 实体 | 关键字段 | 说明 |
|------|----------|------|
| Question（题目） | id、岗位方向、题型、难度、题目内容、参考要点 | 题库中的单道题，参考要点是点评依据 |
| InterviewTemplate（面试模板） | id、名称、岗位方向、环节列表 | 环节 = 题型 + 题目数量 |
| InterviewSession（面试会话） | id、匿名标识、模板配置、状态、起止时间 | 状态：进行中 / 已完成 / 已结束 |
| InterviewRecord（问答记录） | id、会话 id、轮次、题目、用户回答、点评 | 每轮一条，记录完整问答与点评 |
| Report（评估报告） | id、会话 id、总体评价、改进建议、生成时间 | 与会话一对一 |

## 8. 接口需求（前后端边界）

前端依赖以下接口（资源 + 方法 + 用途）：

| 方法 | 路径 | 用途 |
|------|------|------|
| GET | `/api/templates` | 获取预设面试模板列表 |
| POST | `/api/interviews` | 创建面试会话，返回会话信息与第一题 |
| POST | `/api/interviews/{id}/answer` | 提交当前题回答，返回点评与下一题 / 结束标识 |
| POST | `/api/interviews/{id}/finish` | 提前结束面试 |
| GET | `/api/interviews` | 获取当前匿名标识下的历史会话列表 |
| GET | `/api/reports/{session_id}` | 获取某次会话的评估报告 |

> 说明：题库相关能力（题目筛选、抽题）由后端 `engine` / `questions` 模块内部完成，MVP 不单独对前端暴露题库接口。

## 9. 验收里程碑

**MVP 验收标准（DoD）**：

1. 用户可完成「配置 → 面试 → 报告 → 历史回顾」的完整闭环。
2. 预设模板与自定义配置均可正常开始面试。
3. 面试逐题流转、进度显示、提前结束均符合预期。
4. 报告完整生成，历史记录按匿名标识正确隔离。
5. 后端满足严格分层与「每模块一包」的架构要求，`engine` 抽象可支撑后续替换大模型。
6. 全部功能在 PC 浏览器（Chrome / Edge / Firefox）上正常使用。

## 10. 未来迭代方向（非 MVP）

- 接入真实大模型，提升出题与点评质量。
- 语音面试（语音识别 + 语音合成）。
- 动态追问与多轮深入对话。
- 用户注册 / 登录与跨设备同步。
- 移动端适配。
- 题库管理后台界面。
- 面试评分（分维度量化评分）。
- 个性化面试报告与成长曲线。
